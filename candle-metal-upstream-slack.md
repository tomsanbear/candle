# Candle Metal upstream discussion

Hey all! I’ve been busy going down a rabbit hole trying to squeeze as much performance as possible out of MiniCPM-V-4.6, a Qwen3-based model. This required quite a few Candle changes—mostly in the Metal backend—and I’d like to discuss which ones are worth upstreaming.

Full branch: [tomsanbear/lmbrrr](https://github.com/tomsanbear/candle/tree/lmbrrr)

Full comparison against upstream: [huggingface/main...tomsanbear/lmbrrr](https://github.com/huggingface/candle/compare/main...tomsanbear:candle:lmbrrr)

I’ve tried to break the work into independently reviewable changes:

- **Metal `i32` casts:** adds contiguous and strided casts between `i32` and BF16/F16/F32/I64/U32/U8. [Backend routing](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-core/src/metal_backend/mod.rs#L586-L678) · [Metal instantiations](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/cast.metal#L80-L107)

- **Quantized matvec tail-bounds fixes:** prevents out-of-bounds reads/writes when the output row count is not divisible by the kernel’s rows-per-threadgroup. This is a standalone correctness fix. [Commit](https://github.com/tomsanbear/candle/commit/28e284ce)

- **Route matrix-vector shapes through MLX GEMV:** `m == 1` or `n == 1` now tries the dedicated GEMV kernels and safely falls back to GEMM for unsupported layouts. [Routing](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-core/src/metal_backend/mod.rs#L1776-L1848) · [GEMV wrapper](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/kernels/mlx_gemm.rs#L387-L470)

- **BF16 quantized matvec inputs and outputs:** adds direct BF16 activation and destination variants for Q8_0, Q4_K, and Q6_K, avoiding BF16→F32 and F32→BF16 dispatches around each matmul. [Backend integration](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-core/src/quantized/metal.rs#L313-L481) · [Kernel selection](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/kernels/quantized.rs#L24-L296) · [Metal kernels](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/quantized.metal#L2484-L2650)

- **Weight-sharing small-`m` quantized matmul:** multi-column Q8_0/Q4_K/Q6_K kernels reuse each quantized weight load across up to eight activation rows. Routing is limited to sequence-shaped small-`m` inputs, with the existing tile kernel retained where benchmarks showed it winning. [Routing policy](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-core/src/quantized/metal.rs#L322-L530) · [Rust wrappers](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/kernels/quantized.rs#L615-L726) · [Metal kernels](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/quantized.metal#L8592-L8964) · [Correctness test](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-core/tests/quantized_tests.rs#L89-L172)

- **Q4_K decode geometry:** adopts the `2 rows × 2 simdgroups` geometry used by llama.cpp for the BF16 Q4_K decode path. It was bit-identical and measured faster on M3, with `LMBRRR_Q4K_MV_VARIANT=baseline` retaining the historical dispatch for comparison. This one is likely hardware-sensitive. [Production routing](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-core/src/quantized/metal.rs#L382-L431) · [Geometry kernels](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/quantized.metal#L4972-L5422) · [Benchmark/correctness sweep](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/examples/metal_benchmarks.rs#L603-L821)

- **Fused Q4_K GEMV → argmax:** computes the greedy token directly without materializing the full logits tensor. It currently exists as a low-level primitive with a correctness/tie-breaking benchmark, but is not wired into Candle’s general inference path. [Rust wrapper](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/kernels/quantized.rs#L470-L530) · [Metal implementation](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/quantized.metal#L5425-L5590) · [Validation benchmark](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/examples/metal_benchmarks.rs#L151-L310)

- **Fused SwiGLU:** replaces split/narrow + SiLU + multiply with one packed-input operation. There is a public CPU/Metal API and correctness coverage; we’d need to decide how to preserve the previous generic/CUDA behavior before upstreaming it as a replacement. [Public API and implementation](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-nn/src/ops.rs#L41-L552) · [Metal kernel](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/reduce.metal#L1600-L1660) · [Test](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-nn/tests/ops.rs#L294-L316)

- **Partial RoPE:** rotates only the configured rotary dimension and copies the remaining head lanes through in the same dispatch, replacing narrow + contiguous + RoPE + concat. It has CPU/Metal implementations and bit-identical tests. [Public API](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-nn/src/rotary_emb.rs#L580-L770) · [Metal kernel](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/reduce.metal#L1414-L1515) · [Test](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-nn/tests/ops.rs#L317-L365)

- **Fused residual-add + RMSNorm:** writes both the new residual and normalized output in one dispatch. This currently exists only in the Metal-kernels API; its normalized output intentionally avoids the intermediate storage-dtype rounding of the split chain. [Rust wrapper](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/kernels/reduce.rs#L237-L300) · [Metal kernel](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/reduce.metal#L1550-L1607)

- **Fused `x * sigmoid(y)`:** adds the Metal shader for a common output-gating pattern. This is shader-only at the moment and would still need normal Candle/Rust plumbing. [Metal implementation](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/binary.metal#L180-L224)

- **Metal encode-path overhead:** uses read locks for kernel-cache hits, a lightweight hasher, static kernel names where possible, and `RefCell` for encoder-local hazard state already protected by the outer command mutex. These can probably be reviewed as a small runtime-performance series. [Kernel caches](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/kernel.rs#L59-L212) · [Allocation-free binary names](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-core/src/metal_backend/mod.rs#L2000-L2110) · [Encoder state](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal/encoder.rs#L18-L150)

- **Metal buffer-pool and residency behavior:** ordered best-fit buffer buckets, less frequent pool sweeping, and batched residency-set removals. This avoids destroying reusable allocations on every wait and avoids one residency commit per eviction. [Sweep policy and allocator](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-core/src/metal_backend/device.rs#L69-L218) · [Best-fit lookup](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-core/src/metal_backend/device.rs#L575-L585) · [Batched residency removal](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal/residency_set.rs#L41-L63)

- **Metal command submission and synchronization:** adds explicit nonblocking flushes and `MTLSharedEvent` signaling/host waiting. Separately, the branch changes the default compute encoders per command buffer from 50 to 100 and adds opt-in eager enqueueing; those pacing defaults were workload-measured and likely deserve their own discussion. [Shared-event API](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal/shared_event.rs#L1-L49) · [Command integration](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal/commands.rs#L244-L270) · [Pacing/eager enqueue](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal/commands.rs#L15-L170)

- **Fused attention preparation:** combines Q/K head normalization, partial RoPE, Q layout conversion, V copying, and direct K/V-cache writes into two dispatches. The current implementation is BF16-specific and constrained to the target head dimensions, so it may need generalization before upstreaming. [Rust wrappers](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/kernels/attn_prep.rs#L1-L157) · [Metal kernels](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/attn_prep.metal#L1-L163) · [Bitwise test](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/tests.rs#L2451-L2599)

- **GatedDeltaNet kernels:** adds single-token decode, short chunks with rollback capture, a higher-occupancy transposed-state implementation, and tree-verification support. These are substantial but model-specific and would probably belong in their own proposal. [Rust API](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/kernels/gated_delta.rs#L1-L629) · [Decode kernel](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/gated_delta.metal#L1-L171) · [Chunk kernel](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/gated_delta_chunk.metal#L1-L265) · [v2/tree kernels](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/gated_delta_v2.metal#L1-L707)

- **DSPARK Markov-chain kernels:** collapses the draft proposal chain from roughly 5–6 tiny dispatches per step to one or two, supporting Q8_0/BF16 weights and optional vocabulary remapping. The single-dispatch atomic path is limited to a 32,768-token draft vocabulary and has a documented relaxed-atomic memory-model caveat, so this needs careful review. [Rust API](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/kernels/dspark.rs#L1-L202) · [Metal kernels](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/dspark.metal#L1-L368) · [CPU-reference and soak benchmark](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/examples/metal_benchmarks.rs#L1085-L1364)

There are also several experiments I would **not** propose upstream yet: the skinny GEMM was measured slower and is opt-in, while the Q4_K SoA layout, row-tile variants, multi-simdgroup sweeps, and barrier probe are retained mainly as benchmark/research scaffolding. [Skinny GEMM](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/src/metal_src/skinny_gemm.metal) · [Experimental benchmark suite](https://github.com/tomsanbear/candle/blob/lmbrrr/candle-metal-kernels/examples/metal_benchmarks.rs#L498-L1083)

My inclination is to start with the correctness fixes and broadly reusable pieces—`i32` casts, partial RoPE, GEMV routing, BF16 quantized paths, and the buffer/cache improvements—then discuss the hardware-sensitive and model-specific kernels separately. Thoughts on that ordering?
